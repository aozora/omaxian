# Omarchy v4.0.1 → v4.0.2 — port impact

Compared 2026-09-03 against `omarchy-quattro/` at tag **v4.0.2** (`version`
file `4.0.2`) and a temporary clone of tag **v4.0.1**. Omaxian was based on
4.0.1. The bump procedure is [upstream-tracking.md](upstream-tracking.md);
deltas landed in [deltas.md](deltas.md) § *4.0.2*.

**Do not treat this as an Arch upgrade log.** v4.0.2 is a security-focused
follow-up (28 commits, 167 files). Almost all of it is the Arch installer,
SSH, CUPS, Plymouth/SDDM, pacman signatures, webapps, and the Windows VM.
This note is only the slice that can touch the X11/i3 port.

Upstream compare: <https://github.com/omacom/omarchy/compare/v4.0.1...v4.0.2>
· release notes: <https://github.com/omacom/omarchy/releases/tag/v4.0.2>

## Method

`omarchy-quattro/` is gitignored and cloned `--depth 1`, so there is no
in-repo `git diff prev-vendor..HEAD`. The changelog was:

```
git clone --depth 1 --branch v4.0.1 https://github.com/omacom/omarchy.git /tmp/omarchy-4.0.1
diff -ruN /tmp/omarchy-4.0.1/shell omarchy-quattro/shell
diff -ruN /tmp/omarchy-4.0.1/bin/<ported-name> omarchy-quattro/bin/<ported-name>
```

Then each changed `shell/` file that exists in
`omaxian/.local/share/omarchy/shell/` was checked for the 4.0.2 hunks
(`textFormat: Text.PlainText` counts, `syncHidden` IPC).

Quirk: the **v4.0.1** tag still ships `version` = `4.0.0.alpha`. **v4.0.2**
is the first tag that writes `4.0.2`.

## What 4.0.2 actually changes in `shell/`

No new plugins. No `Commons/` edits. No `default/themed/*.tpl` edits. Themes
are identical.

Two kinds of hunk:

1. **`textFormat: Text.PlainText` on `Text {}`** — "Prevent remote image
   injection in shell text elements." Qt `Text` defaults to AutoText; a
   hostile string with HTML/`<img src>` would make the shell issue an
   unauthenticated GET. Applied across Ui controls and almost every plugin
   that renders untrusted labels (tray titles, panel names, speedtest, …).
2. **Bar hide/show reliability** — `plugins/bar/Bar.qml` gained an
   `IpcHandler { target: "omarchy.bar"; function syncHidden() }` because the
   `FileView` watch on `~/.local/state/omarchy/toggles/` can go quiet after
   rapid flag flips, leaving the bar parked off-screen until a shell
   restart. `bin/omarchy-toggle-bar` then calls
   `omarchy-shell -q omarchy.bar syncHidden`.
3. **Notifications plugin only** — `NotificationLogic.js` grew a real
   `stripImageTags` / `styledBody` path so StyledText bodies cannot keep a
   remote `<img src>`. That plugin is not ported (dunst).

## `bin/` that Omaxian actually ships

Of every ported `omarchy-*` that exists in both trees, **only
`omarchy-dns` changed** 4.0.1 → 4.0.2: two `# omarchy:heredoc-expands
paths=none` comments on the NetworkManager drop-in and the
`/etc/systemd/resolved.conf` writer. No behaviour change. Comments copied
into the port; the existing NM / `sv` / `resolvconf` delta stays.

`omarchy-toggle-bar` also changed (the `syncHidden` nudge) but **was not in
the port at all**. Its helper `omarchy-toggle` (flag files under
`~/.local/state/omarchy/toggles/`) was missing too. Both are pure bash,
X11-safe, copied verbatim.

Port-only scripts (no upstream counterpart, ignore for this bump):
`omarchy-monitor-{apply,list,set}`, `omarchy-plugin-check`,
`omarchy-session-is-i3`, `omarchy-theme-next`.

Everything else in the 4.0.2 bin diff is Arch-only:
`omarchy-{agent-usage-codex,brightness-display-apple,dev-link,install-*,migrate,plymouth-*,provision-owner,refresh-plymouth,refresh-sddm,setup-security-*,theme-install,theme-set-browser*,upgrade-to-quattro,version-channel,webapp-*,windows-vm}`.

## Applied in the port (2026-09-03)

Repo only — **not deployed**. `./install.sh && ./deploy.sh` then
`omarchy-restart-shell` is still required on a live session.

1. `plugins/bar/Bar.qml` — `IpcHandler { target: "omarchy.bar"; function
   syncHidden() }` after the existing `FileView` watch. T1/T3 deltas
   untouched.
2. `bin/omarchy-toggle` — verbatim from 4.0.2.
3. `bin/omarchy-toggle-bar` — verbatim from 4.0.2. No i3 keybind (upstream
   has none either); invoke as `omarchy-toggle-bar` /
   `omarchy-toggle-bar on` / `omarchy-toggle-bar off`.
4. `bin/omarchy-dns` — the two heredoc annotation comments.
5. [deltas.md](deltas.md) § *4.0.2* rows, including an explicit "not
   ported" row for `NotificationLogic.js` so the omission is not drift.

Smoke after deploy: `omarchy-toggle-bar` should hide the bar (parked
off-screen, no strut); a second call restores it. `omarchy-shell
omarchy.bar syncHidden` should return without "Function not found."

## Skipped on purpose

| 4.0.2 area | Why |
|---|---|
| `plugins/notifications/` image-tag strip | Notifications stay on dunst |
| agents, clipboard, emojis, lock, menu, dropbox, tailscale, media `BarWidget`, `ActiveWindow` | Already "not ported" in `deltas.md` |
| `plugins/panels/monitor/` PlainText | Different plugin (`omaxian.monitor`) |
| `default/pacman/*`, `default/omarchy/omarchy-menu.jsonc` | Arch / unported menu |
| SSH, CUPS, Plymouth, pacman signatures, webapps, Windows VM, sudoers, `install/`, `migrations/` | Arch installer |

`themes/` and `default/themed/*.tpl` need a re-run of `install.sh` only to
refresh the live share tree; there is no template work in this bump.
